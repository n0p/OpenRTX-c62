# dmr_vocoder tests

Two things are checked, without hardware:

1. **fidelity**: the PCM this decoder produces is compared with the PCM of the
   reference decoder (OpenDMR's own `decoder/` plus its C++ wrapper) on the same
   frames.  1000 frames are checked, and the result is 803/1000 frames bit-exact
   with the rest off by 1 LSB (SNR 106.4 dB), which is the envelope the reference
   has against itself under a different compiler;
2. **it works on the target**: the same sources are built for Cortex-M33 and run
   in QEMU (`mps2-an505`), the PCM is compared with the host build and with the
   reference, and the cost per frame is measured with QEMU's instruction counter.

## Running the Cortex-M33 verification

Needs `gcc`, `arm-none-eabi-gcc` (newlib), `qemu-system-arm` with TCG plugin
support and glib's headers:

```sh
cd lib/dmr_vocoder/tests/qemu
./run_qemu.sh                                       # sources rebuilt here
FIRMWARE_BUILD=../../../build_c62 ./run_qemu.sh     # the firmware's own objects
```

Inputs (all optional): the frame file (default `tests/data/speech.ambe`), the
number of frames (1000) and the reference PCM (default
`tests/data/speech_ref.pcm`, regenerated by `tools/make_ref.sh`, which builds
the reference decoder from the `lib/opendmr` submodule).  The script

- builds the host binary and dumps `host.pcm`;
- builds three Cortex-M33 ELFs — 0, 1 and N frames — with the firmware's FPU
  flags (`-mcpu=cortex-m33 -mfpu=fpv5-sp-d16 -mfloat-abi=hard`) and the same
  per-file options as `lib/dmr_vocoder/CMakeLists.txt`, or links the objects a
  Zephyr build produced when `FIRMWARE_BUILD` points at it;
- runs each in `qemu-system-arm -M mps2-an505` with a plugin that counts every
  executed instruction; the N-frame one also writes `arm.pcm` through
  semihosting;
- compares `host.pcm` with `arm.pcm` and both with the reference
  (`tests/compare_pcm.py`), and prints `instructions/frame` with the resulting
  CPU load at 300 MHz.

`run_qemu.sh` needs `pkg-config --cflags glib-2.0` for the counter plugin; if it
is missing, only the PCM comparison is affected.

## Host-only

`tests/pcm_dump.c` builds on its own and decodes a frame file through the public
API (the firmware entry points):

```sh
gcc -O2 -std=c99 -ffp-contract=off -fno-math-errno -I.. \
    ../pcm_dump.c ../dmr_vocoder.c ../dmr_decoder.c ../dmr_fft.c -lm -o pcm_dump
./pcm_dump ../data/speech.ambe out.pcm
python3 compare_pcm.py ../data/speech_ref.pcm out.pcm
```

`-lm` is only for the host's `fmaf`: on the M33 `__builtin_fmaf` is a VFMA
instruction, and the objects reference nothing but `memcpy` and `memset`.
